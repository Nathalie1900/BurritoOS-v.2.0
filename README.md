# BurritoOS
#### Video Demo:  <[link](https://youtu.be/rLVZ5Uc1vpw)>
#### Description:
**What the project is:**\
BurritoOS is a web application designed to assist people's mental health by helping prevent and manage anxiety crises. It started being just a JavaScript app after finishing week 8 because I was so eager to start building something, but eventually evolved into a more sophisticated app after finishing week 9 and reaching the final project. It has three main features:\
**_1. State Assessment_**: based on a few questions, the page assigns you a "State" (Green, Yellow, Orange or Red) based on some score that later gets the user into one of four different interfaces called Green Mode, Prevention Mode, Regulation Mode and Crisis Mode. Each mode contains a series of recommendations and proposed activities to help the user feel better. Also, the interfaces change visually according to the user's needs in each mental state.\
**_2. Vulnerability Tracker_**: based on a list of affirmations that the user can check and uncheck, it gives the user a score and tells the user how vulnerable he/she is at the moment (a.k.a. "how heavy the backpack they're carrying is") so they know how to take better care of themselves in advance.\
**_3. State History and Vulnerability History_**: The possibility of seeing all the user's previous results, in case someone wants to access that data to look for patterns or a better understanding of themselves.\
\
**Design and technical decisions:**\
One of the main design decisions behind BurritoOS was to separate the responsibilities of the frontend, backend and database. JavaScript is responsible for the interactive parts of the application. For example, statemachine.js receives the answers selected by the user, assigns a numerical score to each answer, calculates the total score and determines which state should be displayed. Once an assessment has been completed, JavaScript uses fetch() to send the result to a Flask route in app.py. Flask obtains the identity of the currently logged-in user from the session and stores the result in the SQLite database. This allows the application to keep permanent records without relying on information about the user's identity sent by the browser.\
Another important design choice was making the interfaces different depending on the user's state. The different modes are not simply the same page with different colors. Prevention Mode and Regulation Mode provide several tools because the user is expected to still have enough capacity to choose between different strategies. Crisis Mode, on the other hand, deliberately reduces the number of choices and uses larger, simpler buttons. The intention is to reduce the amount of information the user needs to process when they are already overwhelmed.\
During development, the State Assessment and Vulnerability Tracker originally existed inside the same large JavaScript file. I later separated them into statemachine.js and vulnerabilitytracker.js. Although both features belong to BurritoOS, they perform different tasks and appear on different pages. Separating them made the code easier to understand, debug and maintain, while also preventing one feature from unnecessarily depending on the other.\
The history features were included because a single assessment only describes one moment. By storing results together with the logged-in user's ID and a timestamp, BurritoOS can display previous assessments chronologically. This gives the user the possibility of observing how their results change over time and identifying patterns in their own data.\
Finally, BurritoOS is intended as a personal support and self-reflection application, not as a medical diagnostic tool. Its states, scores and backpack categories are organizational tools created for the application and should not be interpreted as clinical diagnoses or replacements for professional mental health care.\
\
**What each file does and contains:**\
Inside the **main folder**, **_helpers.py_** contains the code for the decorator that requests login for different routes and for the apology in case somethings fails with the login or registration; **_app.py_** contains all the different routes needed for the web app to function, some leading to an html page and some helping get data from the browser into SQL tables used to store the user's results; and **_project.db_** contains SQL tables that store every state and vulnerability log.\
Inside the **static folder**, **_statemachine.js_** uses JavaScript to dinamically generate the HTML content of the main state assessment and the corresponding Mode based on the user's answers: Yellow Mode contains grounding tools such as a 1-minute breathing timer, Orange Mode contains a series of many checkable quick actions to help the user slow down, Crisis Mode contains a shorter list of actions and a new feature called Identity Cards, which consist of a series of affirmations to help the user remember who they are, where they are, etc., while Green Mode constains just a positive celebratory message; **_vulnerabilitytracker.js_** uses JavaScript to dinamically generate HTML content that consists of a series of checkable risk factors and its corresponding Vulnerability Category based on a total score; and **_styles.css_** provides all the information that's necessary for all the different headings, modes and checkable buttons to have the expected appearance in respect to color and size.\
Inside the **templates folder**, **_login.html_** displays a form that prompts the user for an username and a password, while **_register.html_** displays a form that prompts the user for the same information plus a confirmation of the password; **_apology.html** displays an apology message that changes accordingly to the issue at hand during login or registration; **_layout.html_** displays all the basic UI that doesn't change between the different html pages, such as the navigation buttons; **_index.html_** displays the contents from the statemachine.js file, also serving as a homepage for the app; **_vulnerabilitytracker.html_** displays the contents from the vulnerabilitytracker.js file; **_statehistory.html_** displays data from the SQL table state_history corresponding to all previous state logs of the current user; **_vulnerabilityhistory.html_** displays data from the SQL table vulnerability_history corresponding to all previous vulnerability logs of the current user.
